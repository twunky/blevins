## Implementation evidence

### API routes

- `POST /api/trips/{tripId}/audience/preview` — creator-only preview with resulting mode, saved/current recipients, gains, losses, and preview token.
- `POST /api/trips/{tripId}/audience/confirm` — creator-only whole-audience replacement; stale preview returns `409 Conflict` and requires a fresh preview.
- Existing `GET /api/trips`, `GET /api/trips/{tripId}`, and `PUT /api/trips/{tripId}` remain in place. The ordinary Trip update contract contains no audience fields.

### Persistence and concurrency

No migration is required. The current `FamilyTrips.AudienceType` and `FamilyTripAudienceMembers` rows already represent exactly one mode and the complete recipient snapshot, including membership access versions. The replacement deletes/adds or updates snapshot rows and changes the mode in one `Serializable` transaction using the established Family Group row lock; a failed validation or token comparison occurs before writes. A preview token binds current mode, full saved recipient rows, creator eligibility, proposed recipients and versions, and computed access differences. Commit recalculates these values and compares before saving.

Audience reads and Note reads/writes use the existing current membership-version authorization predicates. No Note row is modified by audience replacement. The existing SQL test harness successfully applied the current migration set to temporary databases. The optional `dotnet ef migrations has-pending-model-changes` CLI check could not run because the API startup project does not reference `Microsoft.EntityFrameworkCore.Design`; no entity or schema change was made.
