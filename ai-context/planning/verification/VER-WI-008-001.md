## Denied audit summary design

- **Aggregation key:** authenticated `ActorAccountId` + `Action` (`ConcernReadDenied` or `ConcernWriteDenied`) + UTC hour bucket. Attempted Concern ID is excluded.
- **Stored metadata:** actor ID, broad category, `Authorized = false`, UTC bucket, first attempt (`OccurredAt`/`FirstAttemptAt`), last attempt, count, and derived 180-day expiry. `ConcernId` and affected participant are null. No request body or Concern/source content is stored.
- **Concurrency:** unique filtered SQL index on actor/category/hour for summary rows; SQL Server `UPDLOCK` plus `SERIALIZABLE` key-range protection updates an existing bucket atomically. Concurrent SQL test confirms 16 attempts yield one row and count 16.
- **Successful events:** retained as individual audit rows without aggregation.
- **Anonymous requests:** Concern HTTP handlers require a current authenticated account; unauthenticated requests retain existing 401 behavior and do not enter the Concern repository. No IP or anonymous identity was added.
