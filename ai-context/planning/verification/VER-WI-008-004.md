## Accessibility review (manual and code-based; no automated scanner is configured)

- **Headings.** One `h1` from the shell. Detail and create use `h2`; cards use `h3`; inline forms use `h4`. The order is logical.
- **Labels and groups.** Every input has a real `<label>`. Grouped choices use `fieldset`/`legend`: categories, source, people with access, handoff target, attempted-by, attempt time or unknown, and restored time or unknown.
- **Validation.** Field errors have IDs referenced by `aria-describedby` and set `aria-invalid`. A focusable `role=alert` summary receives focus on failed submit.
- **Announcements.** A persistent `role=status` region announces created, saved, handed-off, resolved, and task changes. Loading uses `role=status`; errors use `role=alert`.
- **Keyboard and focus:**
  - Everything is a native button, link, or input.
  - Focus moves to the composer or confirmation heading on open, back to the trigger after save or cancel, to the detail heading after create and handoff, to the Resolution heading after resolve, to the unavailable heading, and to the refreshed notice.
  - Escape steps back from the handoff confirmation and closes the choice step (J1 confirms this in a real browser).
  - The existing 3 px focus outline applies.
- **Non-colour cues.** State, task status, and category are always text pills. Timeline dots are `::before` decorations by item type. The visual time column is `aria-hidden` because the item meta repeats both times as `<time datetime>`.
- **Timeline semantics.** `<ol aria-label="Incident timeline, oldest first">`. Related-entry links name the relationship, contributor, and time.
- **Contrast.** Only existing `DEC-070` tokens are used. One new marker colour (`#0e7490`, contact attempts) is decorative.
- **Target size.** Action buttons are at least 2.25–2.5 rem high, and stack full-width at narrow width.

## Implementation choices (non-policy; story § "Implementation choices left to execution")

| Choice | Decision |
|---|---|
| **Component split** | Under `src/app/incidents/`: `incidents` (route container), `incident-list`, `incident-create`, `incident-detail`, `incident-timeline`, `incident-composer` (all entry kinds, including contact attempts), `incident-tasks`, `incident-people`, `incident-coordination` (handoff and resolution), and `incident-provenance-fields` (shared category and source controls). Shared helpers are in `incident-shared.ts`. The API client is `incident-api.ts`. |
| **Route matcher** | `incidentsMatcher` in `app.routes.ts`: one route definition, so the default reuse strategy keeps the same `App` instance. The container reacts to `NavigationEnd`. |
| **Lazy loading** | `@defer (on immediate)` around `<app-incidents>` in `app.html`, with an `@loading` status. The output is a separate `incidents` chunk. |
| **Confirmations** | Inline panels, not `<dialog>`. Escape is supported on the Coordination card. |
| **Navigation state** | Read from `router.currentNavigation() ?? lastSuccessfulNavigation()`. The Concern side uses `openConcernId`. |
| **Drafts after a denied write** | Kept in memory. Composer drafts are keyed by kind and target; task, people, and resolution forms are kept by their components. |
| **Neutral copy and errors** | Helper copy and field error wording are UI-owned, within the meanings the story fixes. |
| **Test queries** | Testing Library is not installed, and no dependency was added. The specs use small local role, label, and accessible-text helpers. They make no CSS-class or layout assertions. |

## Deviations and interpretations (none change behavior or scope)

1. **Timeline times for non-entry items.** For entries, both "Event time …" (or "Event time unknown") and "Recorded …" are shown. Server action items (task, people, handoff, freeze, resolve) have `eventAt = null` by design; the action occurs when it is recorded. They show "Recorded {time}" only, so they are not mislabeled "Event time unknown". No client-side event time is invented.
2. **`e2e/concern-workflow.spec.ts`.** One Home heading locator was updated to "Safety coordination". The file is outside the story's expected-surface table, but the approved Home retitle requires the change. The meaning of the assertion is unchanged.
3. **Concern evidence protection.** Running the existing Concern spec rewrites `site-mockup-alignment/concern-workflow/*.png`. Those files were backed up before the run and restored afterwards, and the MD5 comparison of all 57 files matched. The spec itself was not changed to redirect its output.
4. **Initial bundle.** The initial bundle grew about 10 kB (+1.9%) from the `@defer` and lazy-chunk runtime, while the feature itself (138 kB) is lazy. The story asks that the bundle "not grow materially"; this is recorded for owner judgment.
5. **Navigation state on reload.** Angular restores navigation state when the same history entry is reloaded. A fresh load of `/incidents/new` without state, which J2 tests, gives direct creation. The state carries IDs only, and the server re-validates the Concern lineage, so a restored state cannot widen access.
