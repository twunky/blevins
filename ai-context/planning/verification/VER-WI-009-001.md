### Removal script safeguards (`scripts/remove-scenario-database.ps1`)

Checked in this order; any failure prints `REFUSED: … Nothing was dropped.` and exits **2**; a SQL or drop failure exits **3**:

1. Name supplied and not blank or whitespace.
2. Not `FamilySafety` (checked explicitly, before the pattern).
3. Exact, case-sensitive pattern `^FamilySafety_Invitation_E2E_[A-Za-z0-9]+$`.
4. PRE-EXISTING list file present, readable, not empty, and not containing the name.
5. Manifest path supplied; file present, valid JSON, with `runId`, `databases`, `preExistingAtRunStart`.
6. Name not in `preExistingAtRunStart`.
7. Name recorded exactly once, with the exact spelling.
8. Automatic path: `outcome = passed` and `status = running` (cleanup not yet attempted). `retained` or `cleanup-failed` require a person to pass `-RemoveRetained`; `removed` is always refused.
9. Exactly one matching row in `sys.databases`, and no other session on the database (waits up to 15 s for closed connections to drain; never kills them first).
10. Logs `Dropping scenario database: <exact name> (server, run, spec)`, then runs `ALTER DATABASE … SET SINGLE_USER WITH ROLLBACK IMMEDIATE` and `DROP DATABASE` on `QUOTENAME(@name)` built server-side from a **parameter**, then confirms the row is gone.

Windows integrated security on `localhost`; no credentials. `System.Data.SqlClient` from Windows PowerShell 5.1; no module or package.

## Defects found and fixed during verification

1. **Stale parent PIDs.** `invitation-handoff` passed, but its stop step reported "process tree did not exit (still running: 24392)". PID 24392 was `MoNotificationUx.exe` (a Windows Update notification process started the previous day), whose `ParentProcessId` pointed to a long-dead process whose PID Windows had reused inside the API tree. The harness had **not** stopped it (`taskkill /T` targets only the root PID the harness started). It failed closed: the database was retained and the error raised. Fix: a process counts as a descendant only if it was created no earlier than its parent (`Win32_Process.CreationDate`). All later runs stopped cleanly.
2. **Retained database removable without the switch.** In the first manual test, a database recorded as `retained` with outcome `passed` (keep flag) was dropped without `-RemoveRetained`. It was this run's own database (owned, not PRE-EXISTING, spec passed), so nothing protected was affected, but retention must be deliberate to undo. Fix: automatic removal now also requires status `running`; `retained` and `cleanup-failed` require `-RemoveRetained` (N25, N26).
3. **Over-broad orphan check.** Global teardown counted any process whose command line mentioned `FamilySafety.Api`, so an unrelated concurrent shell command failed three otherwise green single-spec runs. Fix: only `dotnet.exe` / `FamilySafety.Api.exe` processes count. That verification sequence was restarted from the beginning on the final code.
