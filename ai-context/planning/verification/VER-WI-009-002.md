### Defects found on first execution and fixed (second session)

The first session's code had never been run. These defects were found by the first status run and by the safety script, and fixed inside the approved scope:

1. **`Get-ItemsBelow` returned a wrapped list** (`return , $items`). Piping it made every item the whole list, so every run folder was misread as "invalid" and the report stopped. The status run failed closed: nothing changed, as the snapshots showed. Fixed: it now returns `$items.ToArray()`.
2. **Single-action detection.** A one-element pipeline result was unwrapped to a string, so `$actions[0]` was its first character. A Windows PowerShell 5.1 quirk also dropped a trailing value from `@($(…), $(…), $(…))`. As a result `-RemoveDatabase` and `-ClearGenerated` silently ran the status report. Fixed: the action list is now built explicitly.
3. **Ownership index.** `@($genericList)` of PSCustomObjects raises "Argument types do not match" in 5.1. Fixed: plain arrays.
4. **Unknown parameters were ignored.** Without `[CmdletBinding()]`, a switch such as `-RemoveAllRetained` or `-Path` went into `$args`. Fixed: `[CmdletBinding()]` makes unknown parameters an error. The default `-RepositoryRoot` is now resolved in the script body, because 5.1 leaves `$PSScriptRoot` empty in an advanced script's parameter defaults.
5. **Atomic manifest write.** `[System.IO.File]::Replace($tmp, $path, $null)` failed with "The path is not of a legal form", because PowerShell passes `$null` to a string parameter as `""`. This happened for real in verification run 1 (below). The drop was completed and confirmed, exit code 4 reported it, and the harness and tool both surfaced it, so the condition was never silent. Fixed in both scripts with `[NullString]::Value`; a stray `.tmp` is removed on failure. Run 2 and the interruption run then exercised the fixed write successfully.
6. The file was saved without a BOM, so 5.1 would have printed the em-dash labels as mojibake. It was re-saved with a BOM; the logic is unchanged.

| Command | Effect |
|---|---|
| `.\scripts\test-artifacts.ps1` | Read-only status. It shows active runs, the run groups, retained databases (run, database, spec, result, label, reason, created date and age, and whether removal is offered), interrupted runs with their ownership evidence and the exact-name command, manifest/server mismatches, reconciliation label counts, run records by state with sizes, stale removable records, protected and unknown-ownership databases (and ambiguous ownership), the generated folders, unexpected root entries, and the safe next steps. |
| `-RemoveDatabase <exact name>[,…]` | Dry run: ownership proof (owning run, manifest path and SHA-256, spec, outcome, status, note, existence, label, run-start snapshot check) and the proposed delegated command. Any refused name refuses the whole command. |
| `… -Execute` | For an interrupted entry, it first proves again that nothing is alive and the manifest hash is unchanged, then records `retained` with a history entry. It then calls `remove-scenario-database.ps1 -DatabaseName <name> -ManifestPath <owning manifest> -RemoveRetained` and confirms absence with `list-scenario-databases.ps1`. |
| `-RemoveRunRecords [-RunId <id>,…] [-Execute]` | Without `-RunId`, only `Resolved` folders. With an exact `-RunId`, also `Cited`, `CitationUncertain`, and `InterruptedNoDatabase` folders. It never removes `Invalid`, `Active`, `HoldingDatabases`, or `InterruptedHoldingDatabases` folders. |
| `-ClearGenerated [-Execute]` | Empties only `e2e/test-results/`, `e2e/captures/` (keeping its `.gitignore`), and `dist/verification/`. Each must lie inside `src/FamilySafety.Web/` and contain no junction or symbolic link. Deletion works bottom-up and never follows a link. |

**Guards for every action.** The tool refuses (exit 2) when SQL Server cannot be queried, when the process list cannot be read, when port 5080 is in use, when any run is active (a recorded `runnerPid` whose command line names Playwright, or a recorded `apiPid` whose command line names its scenario), or when the run folder cannot be listed. Exit codes: 0 = report, dry run, or done; 2 = refused; 3 = failure; 4 = a delegated drop succeeded but the manifest was not updated.

**Database safety and delegation.** Candidates come only from manifest records reconciled with a live `sys.databases` query, never from a prefix, a wildcard, or age. The tool's own checks are: not `FamilySafety`; the exact pattern; not PRE-EXISTING; no invalid or unreadable run folder that could also claim the name; recorded in exactly one valid manifest with the exact spelling; not in that run's start snapshot; not active; status `retained` or `cleanup-failed`, or `starting` or `running` in a run proven interrupted; and present on the server. Then `remove-scenario-database.ps1` repeats all of its WI-009-001 checks, unchanged.

**Citation (D2).** The tool searches every non-image file under `ai-context/`, `claude-handoff/`, `codex-handoff/`, `docs/`, `scripts/`, and `README.md`. A run counts as cited if any file contains its run ID, its 8-character suffix, a database name it records, or that name's first 8 hexadecimal characters. The short forms can over-protect, which is the safe direction. A missing location or an unreadable file makes every run `CitationUncertain`.
