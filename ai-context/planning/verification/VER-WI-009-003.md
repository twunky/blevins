### D4 mechanism (as implemented)

- Main-navigation and landing links pass router state `{ focusHeading: true }`.
- `App` keeps a reference to the navigation that created it: `router.currentNavigation()`, read when the router constructs `App` during route activation.
- At the end of `ngOnInit`, if that navigation's trigger is `imperative`, its `previousNavigation` is not null, and its state carries `focusHeading`, one `afterNextRender` callback focuses `main h1`.
- Refresh is excluded because it is the router's initial navigation, which has no `previousNavigation`. Back and forward are excluded because their trigger is `popstate`. Navigations from in-page buttons (`navigate()`) carry no state, so they are excluded too.
- Data loads, Family switches, and Incident sub-screen changes do not create a new `App`, so they never reach this code.
- There is no router-event subscription and no global side effect.
- The story suggested reading `lastSuccessfulNavigation()` inside `afterNextRender`. The component test showed that `ngOnInit` can run after `NavigationEnd`, when `currentNavigation()` is already null. Reading the navigation at construction is equally explicit and is reliable in both cases.
