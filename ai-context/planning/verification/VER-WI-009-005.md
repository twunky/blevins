### Authorize-first decision (as implemented)

```text
ROUTE (ID only) → isItemId? no → generic unavailable, no request
              → GET item → 404 → generic unavailable (no Family call)
                         → 200 → adoptAuthorizedItemFamily(item.familyGroupId, kind)
                                   wait for the Family list (a failed list shows the membership error + Retry and waits)
                                   absent? refresh /api/family-groups/mine once, wait again
                                   still absent → Trip: 'retained' | others: 'unavailable'
                                   current → 'current'
                                   otherwise → clear + switch + load the Family + "Switched to {name from own list}." → 'switched'
                         → host renders after the promise resolves
```

- Hosts set their visible item only after the decision.
- There is one item read per open. After creating a Concern, the Concern is not read again: the matcher keeps the component, and `ngOnChanges` skips a re-read when the selected Concern matches the URL.
- The OD-B refresh keeps the current selection's loaded state when the refreshed list still selects it, so a refresh alone does not reload Family-scoped data.
- **Trip re-keying:** the Trip item host is **not** re-keyed on the Family. There is a single Trip read, and the switch updates its inputs. The list route keeps its existing re-key.

## Deviations

1. **Concern route uses the OD-G matcher alternative.** `/concerns` and `/concerns/:id` share one matcher, as the Incident routes do, so the create recovery state is kept without carrying anything in navigation state.
   - **Consequence:** list → Concern item does not re-create the shell, so D4 does not move focus to the `h1` there. This matches the Incident list → item behavior.
2. **Family selector `[selected]` fix.**
   - **The defect:** on a fresh shell with a remembered selection, the `<select [value]>` was applied before its `@for` options existed. The selector could then show "Choose a Family" while a Family was selected. This was pre-existing; the unit test exposed it.
   - **Why it was fixed here:** AC-17 requires the selector to show Family 1 until the 200.
   - **The fix:** `[selected]` on the options. The template change only; there is no behavior change.
3. **Trip item page:** the "Create Trip" toolbar is shown on `/trips` only, not on `/trips/:id`. A cancelled create on the item page would otherwise show an unloaded list. Trip creation is unchanged on `/trips`.
4. **Event and Plan item pages** have no page subtitle. The `h1` is the area title. The Trip and Concern item pages keep their area subtitle.
5. **"Back to Concerns" and the Incident lineage link** are now links. The lineage link keeps its quiet text style.
6. **Cross-Family "open by URL with Family 1 already selected"** is exercised by a pushState/popstate in-app navigation in Playwright. A typed URL reloads the page and ends the session-only selection (`REQ-UX-011`); that case is covered separately as the "none selected" direct entry.
