## Implementation

- **Arrival:** `continueToHome()` navigates to `/home` with `{ focusHeading, joinedFamilyId }` navigation state.
  - The new `App` instance reads `joinedFamilyId` only from an imperative navigation that has a previous navigation, following the Event-create pattern.
  - It announces after its own `/api/family-groups/mine` load, and only if that Family is the selected one.
  - The name comes from the membership list, never from invitation data.
- **Exits:** "Go to Home" renders whenever the invitation token is gone or an invitation error is shown.
- **No-Family guidance:**
  - Home has a `section.home-no-family` card with the O4 copy and one `/me` link.
  - The shared "Family context required" prompt has the concise copy and the same link.
- **First choice:** `switchCurrentFamily()` no longer redirects to Home after a first choice.
- **Invite feedback:** rendered in the Invite card, on Family Settings only. The top-of-page invitation messages were removed, and the Invite card help was consolidated.

### Duplicate no-Family correction (O11)

- **Cause:** `.page-content { display: grid }` overrides the browser's `[hidden]` rule, so the container stays visible even when its `[hidden]` binding is true. Section-level `[hidden]` still works because of `.page-content > [hidden] { display: none }`. The container rule was **not changed**.
- **Affected views (verified):** `/family`, `/events`, `/events/all`, `/events/new`, and `/plans`, each showing the shared prompt above an inner no-Family state:
  - Events and Plans showed "Family access begins through an administrator invitation or controlled setup…".
  - The Family directory card showed "You do not currently have an active family group.".
- **Correction:**
  - `app.ts`: the shared prompt's existing condition moved unchanged into `familyContextPromptShown`, plus a new `sharedNoFamilyPromptShown` (prompt shown, Families loaded, zero active Families).
  - `app.html`:
    - the Events and Plans inner no-Family paragraphs render only when `!sharedNoFamilyPromptShown()`;
    - the Family dashboard section adds `|| sharedNoFamilyPromptShown()` to its own `[hidden]`.
  - The inner branches were kept, not deleted.
- **Preserved:**
  - **Home profile-load error:** still rendered. Angular asserts it is visible, and that its only `[hidden]` ancestor is `.page-content`.
  - **Membership-error prompt:** shows the error and Retry, with no no-Family copy beneath.
  - **Multi-Family "Choose your current Family above…" prompt:** unchanged, with its page content unchanged.
  - **Trips:** usable with no Family and no prompt.
  - **Selected Family:** Events, Plans and Family render normally.
- **Mutation check:** with `sharedNoFamilyPromptShown` forced to `false`, the six O11 tests fail; the code was then restored.

## Privacy regression

All checks pass.

- **Preview:** shows only "Development Adult invited you to join Development Family.": no email, recipient name, member list, count, capacity, or administrator detail.
- **Unavailable is uniform, with no reason given:**
  - the declined link, a made-up token, and the used link after joining (already a member) render identical text;
  - the server previews for all three are byte-identical (404, same body).
- **Acceptance grants membership only:** B's `/api/family-groups/administered` stays empty, and B's Family Settings shows no Invite card.
- **Token use:** after Accept, the invitation token appears in exactly one request, the accept call. The URL no longer contains `invite=`. Nothing after acceptance uses invitation data, and the announcement names the membership-list Family.
- **Capacity:** the browser-only 409 wrote nothing; B's membership list was unchanged.
- **Selected Family is UI context only:** an unknown `joinedFamilyId` in navigation state announces nothing; on refresh with two Families the selection starts empty (`REQ-UX-011`).
- **No cross-Family leakage:** B sees A's profile only as A shares it (all private fields null); no A data appears in B's session.
- **No self-service Family creation:** no create, find, join-code, request, or search wording on Home or any Family-required page.
