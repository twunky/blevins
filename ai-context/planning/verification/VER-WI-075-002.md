Routes are `/` (invitation-aware entry, ordinary entry redirects to `/home`), `/home`, `/family`, `/events`, `/plans`, `/trips`, and `/me`; unknown paths redirect Home. A persistent shell shows the current Family, Home/Family/Events, a Plans & Trips group with distinct route controls, and Me / Settings. Existing screen and Trip components are reused. Family administration remains in Family and is gated by the selected Family's existing administrator eligibility.

`CurrentFamilyContext` is an in-memory signal. One active membership selects itself; multiple require the shell selector, with no response-order choice; zero selects none. Membership failure has its own retry state. Selection is not sent to the API as a permission claim. Existing server authorization still decides every read and write. On a Family switch, directory/member, relationships, Event/Plan lists, forms, selections, messages, and contextual invitation state reset. Request versions reject stale reads; Family-scoped in-flight member and write subscriptions are canceled; the Trip child is keyed by current Family so its list/detail/forms and subscriptions are destroyed and loaded anew. The own profile is retained. A Trip created by the user in a Family they no longer actively belong to remains available in a separate, labeled creator list, without a directory path or active-membership claim.

Browser smoke covered a Development fixture and a narrow viewport, not a full device/accessibility matrix. The next bounded Phase 7.5 proposal should address **Home and feature empty states** using implemented data and authorized next actions, without adding deferred domain capabilities.
