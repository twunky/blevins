## Shared visual tokens and presentation patterns

- **Tokens:** deep evergreen primary, stronger evergreen hover, muted sage accent, warm neutral page, white and pale surfaces, charcoal-green text, slate-green muted text, border, success/warning/error backgrounds and text, focus color, spacing steps, three radii, and a restrained shadow.
- **Patterns:** centered app frame, shell header, current-Family pill/selector, active navigation, page content surface, focused state surface, section/form grouping, admin section, member/item summary cards, Home preview/low-data panels, status messages, button hierarchy, action rows, Trip detail/Notes/audience panels, and responsive field grids.
- **Implementation choice:** shared SCSS was sufficient; no reusable Angular component or new dependency was added. Existing markup and behavior were retained wherever a class could provide the presentation layer.

## Area implementation summary

- **Shell/navigation:** separated the shell header from page content; constrained content to 72 rem; added visible and programmatic current-route state, a clear current-Family treatment, responsive wrapping, and a separate Development panel.
- **Home:** styled the Family welcome, authorized Event/Plan/Trip previews, metadata, actions, and reassuring low-data state while retaining WI-075-003 ordering, cap, scope, and wording.
- **Family:** separated directory, member detail, relationships, and structural administration into scannable sections with consistent cards and actions.
- **Events:** grouped existing fields and audience rows, clarified action hierarchy, and aligned lists/details/empty and status states with the common vocabulary.
- **Plans:** applied the shared form/list/status/action hierarchy while keeping Plans visually lighter and behaviorally distinct from Trips.
- **Trips:** organized create/edit fields, optional travel detail, contacts, list/detail, Notes, and creator-only audience editor. The gain/loss preview is a bordered review surface with explicit text and a distinct confirm action.
- **Me / Settings:** improved profile section hierarchy, helper text, privacy visibility controls, responsive columns, and Save action presentation.
- **First-use/administration:** applied focused surfaces and status treatments to invitation/handoff states; refined only the existing invite/resend/revoke form and structural-role explanation.
- **Mockup boundary:** adopted warm palette, calm surfaces, hierarchy, grouped forms, and summary-card ideas. No mockup-only workflow, permission, navigation decision, or capability was added; the references were not reproduced literally.
