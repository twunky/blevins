## Implementation evidence

The script saves the caller's current `WarningsNotAsErrors` value, adds only `NU1900` before invoking `dotnet run`, and restores the original value in `finally` after the child process ends. If the caller already has warning exceptions, the script preserves them and appends `;NU1900`. This scopes the exception to the invitation scenario's `dotnet` process and does not change `Directory.Build.props`, a project file, application source, or CI configuration.

A focused scope check used a preexisting value of `CS1591`. The child invocation observed `CS1591;NU1900`; after the script returned, the caller again observed `CS1591`.

## Runtime evidence

The first verification attempt inside the restricted execution sandbox showed both API and Infrastructure NU1900 messages as warnings and completed restore/build, then stopped on the sandbox's local SQL encryption and Windows event-log restrictions. The same script was rerun on the normal host to perform the required database and health checks.

The host run retained the current vulnerability-feed failure and printed:

```text
FamilySafety.Api.csproj : warning NU1900: Error occurred while getting package vulnerability data: Unable to load the service index for source https://api.nuget.org/v3/index.json.
FamilySafety.Infrastructure.csproj : warning NU1900: Error occurred while getting package vulnerability data: Unable to load the service index for source https://api.nuget.org/v3/index.json.
```

Restore and build continued. Entity Framework applied the migrations through `20260927100000_PlanNotes`, inserted the dedicated invitation-scenario Accounts, AdultProfiles, FamilyGroup, active membership, and administrator assignment, and then the API reported:

```text
Now listening on: http://localhost:5080
Application started.
Hosting environment: Development
```

`GET http://localhost:5080/health` returned HTTP `200` with body `Healthy`. The verification API was then stopped normally. No WI-075-005 preflight steps were performed.

## Ordinary build and security boundary

A normal `dotnet build src/FamilySafety.Api/FamilySafety.Api.csproj` outside the scenario script succeeded with zero warnings and zero errors when the feed was reachable for that invocation. Its evaluated properties remained:

```text
TreatWarningsAsErrors = true
WarningsNotAsErrors = (empty)
NuGetAudit = true
NuGetAuditMode = all
```

Repository search found no global audit disablement or warning exception. Outside the scenario script, NU1900 therefore remains governed by the global warnings-as-errors policy. The script names only NU1900; it does not suppress or exempt NU1901, NU1902, NU1903, or NU1904. No CI file was changed.
