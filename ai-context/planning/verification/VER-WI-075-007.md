## Implementation and boundary

- **Persistence mechanism:** `sessionStorage`, key `family-safety.development-identity`.
- **Stored value:** Only the selected Development account ID. The browser tab/session lifetime allows that selection to survive the invitation link's document reload; no Family, profile, Event, Plan, Trip, private-item, or authorization data is stored.
- **Development-only guard:** The identity picker is initialized only in Angular Development mode. Persisting a switched identity also checks `isDevMode()`. No production login, cookie, token, or session behavior was added.
- **Bootstrap:** The Development identities allowlist loads first. The stored ID is restored only when it matches an allowlisted identity; an unknown ID is removed and the fixture default is used.
- **Switching:** Switching writes the new selected ID, clears current Family context and outbox state, then navigates through a replacement workspace as before. Existing route destruction continues discarding prior forms, lists, details, selections, and subscriptions. Family context itself is not persisted.
- **Security boundary:** The ID is test selection state only. Server authorization remains authoritative; preserving identity or routing to an invitation grants no access. No server code or authorization rules changed.
