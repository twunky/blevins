## SCSS budget and future style-maintenance note

The production build reports `app.scss` at **7.62 kB**, against a **4 kB warning** and **8 kB error** threshold. WI-075-010 reported **6.04 kB** after its shared-style consolidation, so WI-075-011 added approximately **1.58 kB**. The added rules correspond to real Home-specific composition needs: intro, conditional suggestion, overview grid, preview panel behavior, and separate preview-detail presentation. Their selectors are Home-scoped and reuse the existing tokens and shared button/focus treatments; the growth is not a duplicated shared pattern. The warning is not suppressed or raised. Current headroom to the error threshold is approximately **0.38 kB**.

This is a style-maintenance concern for later PRP-027 planning. Further substantial screen-specific styling should avoid accumulating in `app.scss`; as screens have appropriately scoped component styles, place their local presentation there and keep shared tokens/primitives in the shared stylesheet. This note does not authorize a component split or SCSS refactor in WI-075-011.

## Focused accessibility and privacy checks

- The Home shell retains `h1` Home. Welcome and Family overview are `h2`; each preview retains its labeled `h3` ID and list structure. The Family overview section uses `aria-labelledby`.
- Existing action accessible names and button elements are unchanged. On the real low-data Home at 390 px, View Family and each Open action measured 44 CSS px high. Focus on View Family showed the shared 3 px solid focus outline.
- Home loading/status and error/alert markup was not altered. The low-data state remained distinct from load failures in the existing Angular suite.
- New text/background pairs use existing tokens. Calculated contrast: strong heading on soft surface 9.65:1; muted detail on white 6.13:1; muted intro on primary-soft 5.32:1; body text on low-data surface 12.78:1. This is a focused check, not a full accessibility certification.
- `app.ts` was unchanged. Existing Home Event/Plan/Trip filters, sorting, three-item caps, current-Family Trip boundary, Family switching, audience/access behavior, and APIs were not touched. The existing Home behavior suite passed.
